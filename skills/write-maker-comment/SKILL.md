# Write maker comment

## Steps

1. Read `<launch-folder>/launch.json` — especially `maker.voice_notes`, `product.what_it_does`, `who_its_for`, `ph_offer`.
2. Read `docs/assets.md` → "Maker comment" anatomy.
3. Write `copy/maker-comment.md`: fill the anatomy sections, then produce the full draft (120–250 words) in the maker's voice — first person, plain words, specific details. No press-release tone.
4. End with the specific feedback ask. Generic "let me know what you think" is a failure — ask about a real surface (onboarding, pricing, a named feature).
5. Report the draft and flag any missing inputs (no offer set, vague who_its_for).

## Rules

- Include the PH offer only if `ph_offer` is actually set — never invent one.
- The comment must contain one concrete detail only the maker would know. If launch.json lacks it, ask the user or mark `<add a detail only you know>` so they fill it.
